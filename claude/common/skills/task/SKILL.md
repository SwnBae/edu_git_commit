# /task — 작업 시작

사용자가 새 작업을 요청했을 때 코드를 쓰기 전에 아래 순서로 진행한다. 인자(`$ARGUMENTS`)가 있으면 그것이 작업 설명이다.

1. **요구사항 읽기**: 작업 설명을 끝까지 읽는다. 관련 파일과 설치된 규칙(`.claude/rules/`)을 확인한다.
2. **가정 정리**: 요청에 없는 부분을 어떻게 해석했는지 나열한다. 결과가 크게 달라지는 불명확한 점은 코드를 쓰기 전에 사용자에게 묻는다.
3. **검증 가능한 목표**: "무엇이 되면 끝인지"를 확인 가능한 문장으로 쓴다. 예) "존재하지 않는 id 조회 시 404가 반환되고 테스트가 통과한다."
4. **계획**: 여러 단계가 필요한 작업은 단계별 계획과 각 단계의 확인 방법을 제시한다. 영향받는 파일을 목록으로 적는다.
5. **승인 대기**: 계획에 대해 사용자 승인을 받은 뒤 구현한다. 한두 줄짜리 수정은 계획 없이 바로 진행해도 된다.
6. **구현**: 요청한 범위의 최소 변경만 한다. 요청하지 않은 기능, 추상화, 리팩터링을 추가하지 않는다.
7. **마무리**: `/done` 체크리스트로 확인한다.

참고: 이 skill의 절차는 킷 작성자가 정한 기본안이다. 팀 방식이 다르면 이 파일을 고친다.
