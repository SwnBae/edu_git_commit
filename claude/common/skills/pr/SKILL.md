# /pr — PR 생성

1. `git-convention` 규칙을 읽는다.
2. 기준 브랜치(`<<결정: 예) main>>`와 현재 브랜치의 차이를 확인한다: `git log`, `git diff <기준>...HEAD`.
3. `/done` 점검이 통과했는지 확인한다. 안 했으면 먼저 하자고 제안한다.
4. 초안을 만들어 사용자에게 보여준다.
   - 제목: 커밋 메시지 형식
   - 본문: 변경 요약, 변경 이유, 테스트 방법, 영향 범위, 리뷰어가 볼 지점
5. **사용자가 초안을 승인하면** 그때 push와 PR 생성(`gh pr create`)을 한다. 승인 전에는 push하지 않는다.
6. 본문 끝에 붙일 문구(도구 표시 등)는 `<<결정>>`. 세션이 요구하는 문구와 다르면 사용자에게 묻는다.
