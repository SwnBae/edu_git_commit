# 클린 코드

수치 기준은 고정하지 않는다. `<<결정>>` 자리는 프로젝트가 채운다.
근거: [자료] Naver·Google Java 스타일 가이드에는 메서드 길이·클래스 크기의 수치 제한이 없다. 복잡도는 Sonar Cognitive Complexity 같은 도구 기준을 쓸 수 있다.

## 이름
- 이름은 의도를 드러낸다. 축약어와 `data`, `info`, `temp`, `Manager`, `Helper` 같은 모호한 이름을 피한다.
- boolean은 `is`, `has`, `can` 등 질문형으로 짓는다.
- 클래스는 명사, 메서드는 동사로 시작한다.

## 함수
- 함수는 한 가지 일만 한다. 길이 가이드: `<<결정: 줄 수 또는 "화면 한 번에 보이는 정도">>`
- 중첩은 early return(guard clause)으로 줄인다. 최대 들여쓰기 깊이: `<<결정>>`
- 매개변수 개수 가이드: `<<결정>>`. 많아지면 객체로 묶는다.
- boolean 플래그 매개변수로 동작을 분기하지 않는다. 메서드를 나눈다.
- 반환 타입: 컬렉션은 null 대신 빈 컬렉션을 반환한다. 값이 없을 수 있으면 `Optional`을 반환한다(필드·매개변수에는 쓰지 않는다).

## 클래스
- 클래스는 변경 이유가 하나다. 책임이 둘 이상이면 나눈다.
- 불변을 기본으로 한다. 필드는 `final`, setter는 만들지 않는다. 상태 변경은 의도가 드러나는 메서드로 한다.
- 생성자 주입만 쓴다. 필드 주입(`@Autowired` 필드)은 쓰지 않는다.
- Lombok: `@Data`, `@Setter`는 쓰지 않는다. 엔티티에 `@Builder`·`@AllArgsConstructor`를 클래스 레벨로 열지 않는다.

## 값과 주석
- 매직 넘버·문자열은 상수, enum, 설정값으로 뺀다.
- 주석은 "왜"를 설명한다. 코드가 말하는 "무엇"을 반복하지 않는다. 주석 처리한 코드와 죽은 코드는 남기지 않는다.
- TODO에는 맥락을 적는다: `TODO(<<결정: 식별자>>): 사유`

## 예외와 null
- 예외를 삼키지 않는다(빈 catch 금지). 잡았으면 처리하거나, cause를 보존해 다시 던진다.
- 제어 흐름에 예외를 쓰지 않는다.
- 외부 입력은 경계에서 검증하고, 내부에서는 null을 전파하지 않는다.

## 변경 범위
- 요청과 무관한 리팩터링·포맷 변경을 섞지 않는다. 변경은 요청한 목적에 필요한 줄로 한정한다.
