# 로깅

- SLF4J를 쓴다(`@Slf4j`). `System.out`, `printStackTrace()`는 쓰지 않는다.
- 파라미터 치환을 쓴다: `log.info("order created. orderId={}", id)`. 문자열 연결로 로그를 만들지 않는다.
- 로그 레벨
  - ERROR: 즉시 사람이 봐야 하는 실패(처리 불가능한 오류).
  - WARN: 처리했지만 비정상인 상황(재시도 후 성공, 폴백 사용 등).
  - INFO: 업무적으로 의미 있는 이벤트(생성·상태 전이·외부 연동 시작/종료).
  - DEBUG: 개발 중 상세 추적. 운영 기본값에서는 꺼진다.
- 비밀번호, 토큰, 키, 개인정보(주민번호·전화번호·이메일 원문 등)는 로그에 남기지 않는다. 필요하면 마스킹한다.
- 예외는 한 곳에서만 로그로 남긴다. "로그 남기고 다시 throw"를 반복하면 같은 오류가 여러 번 기록된다. 기본 위치는 전역 예외 처리기다(`exception-handling` 규칙 참조).
- 예외를 로그에 남길 때는 스택트레이스를 포함한다: `log.error("...", e)`.
- 요청 추적 ID(MDC): `<<결정: 사용 여부와 키 이름>>`
- 반복문 안의 INFO 로그, 대용량 객체 전체 출력은 피한다.
