# Git 컨벤션

`<<결정>>` 표시는 프로젝트가 값을 채우는 자리다.

## 커밋·푸시·PR
- 사용자가 요청하기 전에는 commit, push, PR 생성을 하지 않는다.
- main(또는 기본 브랜치)에 직접 커밋하지 않는다. 작업 브랜치에서 한다.
- force push는 사용자가 명시적으로 요청한 경우에만 한다.
- 커밋 하나는 하나의 목적만 가진다. 서로 다른 목적의 변경(리팩터링과 기능 추가 등)은 커밋을 나눈다.
- 비밀 값(키, 비밀번호, 토큰)과 `.env`, 빌드 산출물은 커밋하지 않는다.

## 브랜치 이름
- 형식: `<<결정: 예) type/short-description>>`

## 커밋 메시지
- 형식: `<type>(<scope>): <subject>` — `<<결정: 언어(한글/영문), subject 길이 상한>>`
- type: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `build`, `ci`
- subject는 "무엇을 했는지"를 현재형으로 쓴다. 본문에는 "왜"를 쓴다.
- 트레일러(Co-Authored-By 등): `<<결정: 사용 여부>>`. 세션이나 도구가 따로 요구하는 문구와 이 규칙이 다르면 사용자 지시를 우선하고, 모호하면 커밋 전에 사용자에게 묻는다.

## PR
- 제목은 커밋 메시지 형식을 따른다.
- 본문: 변경 요약, 변경 이유, 테스트 방법, 영향 범위.
- 리뷰 전에 `/done` 체크리스트를 통과시킨다.
