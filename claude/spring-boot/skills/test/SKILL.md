# /test — 테스트 작성·실행

인자(`$ARGUMENTS`)는 대상 클래스/패키지 또는 "실행"/"실패 분석" 같은 지시다.

## 작성할 때
1. `.claude/rules/`의 `test-given-when-then.md`, `test-strategy.md`를 읽는다.
2. 대상 코드를 읽고, 테스트 종류를 정한다(단위 / `@WebMvcTest` / `@DataJpaTest` / 통합). 가장 낮은 비용의 종류를 우선한다.
3. 검증할 행동 목록을 먼저 사용자에게 보여주고(정상, 경계값, 예외), 합의되면 작성한다. 작은 요청이면 목록을 한 줄로 요약하고 바로 진행한다.
4. Given-When-Then 형식으로 작성한다. 테스트 하나에 행동 하나.
5. 실행해서 통과를 확인한다. 통과시키려고 운영 코드를 바꿔야 하면 바꾸기 전에 이유를 말한다.

## 실행·분석할 때
1. `<<결정: 명령. 예) ./gradlew test --tests '<패턴>'>>`을 실행한다.
2. 실패하면 첫 실패의 원인을 로그에서 확인해 보고한다. 추측하지 않는다. 원인이 코드 결함인지 테스트 결함인지 구분한다.
3. 수정은 사용자가 요청한 경우에만 한다.

## 하지 않는 것
- 커버리지를 채우기 위한 의미 없는 테스트 작성.
- 외부 시스템 실제 호출.
- 실행하지 않은 테스트를 통과했다고 보고.
